---
title: "10.2. Workflow"
---

Developing a web special or microsite is a collaborative process that moves from ideation and requirements planning to a live website. The Web Editor typically heads the project’s planning and collaborates with the sections involved for the content and some assets. Meanwhile, a selected group of web development staffers form the project’s internal design and development team—led by a lead designer and/or lead developer—is responsible for its internal workflow—including task division, file organization, coding conventions, and Git repository management. Sometimes, the designer and developer roles are the same person; other times, they are separate. The number of people involved also varies, but typically ranges from 3 to 5.

While the internal project team decides its specific process, the general workflow involves these key stages, similar to the software development lifecycle. However, this process may be flexible depending on needs and time.

1. **Planning and consultation.** Begin by conceptualizing the project. This depends on whether the project is a digital counterpart or an independent project by Web. Plan as well for a target release date. Once the concept is approved, a project team of designers and developers is formed. Collaborate with the relevant section editors (a writing section, A&G, and/or Layout) to plan the content and gather assets.   
     
2. **Design and approval.** The stage is an iterative cycle. Start with low-fidelity wireframing to map out the site’s structure, user flow, and information hierarchy. Next, create high-fidelity mockups showing exactly how the final site will look. Be sure to design for mobile, tablet, and desktop views.

   Share the mockups to the Web editor and executive editors for feedback, revise the design, and repeat the process until a final version is approved. It’s critical for designs to be approved before coding begins, as it’s much faster to change a design that to rewrite code.

   Nonetheless, this process can be done in parallel chunks—a portion of the design can be finalized and sent to development while designers begin to work on the next portion.

3. **Development and testing.** Development begins once a design or the first portion of a design in a parallel workflow is approved. Like the design phase, development is an iterative process.

   Developers build the website based on the approved mockups, working in cycles of coding, testing, and refining the code. Note that minor revisions to the design can occur during development.

   It is highly recommended to deploy the site to a private staging link for continuous testing and review. If this isn’t feasible, the final review can be done on the live site after deployment or on screen recordings shared via the team’s group chat.

4. **Deployment and launch.** Once ready for review or approved for release, upload the website files to the server (see section 7.3) and create the subdomain (see section 7.4). Perform a final check on the live URL; it’s common to make minor code revisions and re-upload files during this stage to fix bugs found on the live server.

   Finally, the Web editor coordinates with the Layout editor for the pub used for the social media launch.
